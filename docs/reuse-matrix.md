# 旧项目资产与复用矩阵 v1

## 原则

1. 旧项目只读；不复制、移动、重命名或覆盖任何旧文件。
2. 优先复用**规格、约束、测试思路和失败案例**，不整体迁移代码。
3. 三仓根目录均未发现许可证文件。在授权明确前，不把旧项目代码直接复制进 Zevorinth。
4. 任何机制进入新项目前，必须有调用链、失败处理、负向测试和可验证消费点。

## 下次深入检查的问题

### AutoCodePlay

1. `AgentLoop` 的最大步数、工具超时、异常和用户中断分别如何结束？
2. 审批拒绝是否会阻止工具执行，而不只是生成一条警告？
3. 路径逃逸、符号链接和覆盖操作是否有真实负向测试？
4. 会话状态如何区分完成、失败、中断和从未执行？
5. 哪些安全与测试设计可以在不复制实现的前提下重新表达？

### hermes_seed_副本11

1. `manifest_runner` 的最小输入、输出和退出码是什么？
2. 事件日志如何保证顺序、原子性和故障后的可读性？
3. 恢复是否可重复执行而不会产生重复副作用？
4. 产物审计实际验证了哪些属性，哪些只是记录路径？
5. 哪些测试能在无模型、无网络条件下独立运行？

### zh / BLASTEMA / FAMA

1. 三态在任务、工具和验证结果中的准确语义是什么？
2. 进程被杀后如何判定运行被中断，而不是成功或未运行？
3. 危险操作被拒绝时，如何保存原因且不执行副作用？
4. 反证测试如何区分“守卫捕获缺陷”和“测试装置自身崩溃”？
5. 哪些规格适合直接抽象成 Zevorinth 的验收测试？

## v1 决策

第 1 阶段不复制旧项目代码。先用标准库实现一个自包含、可测试、可恢复的最小闭环；随后针对上述问题做定向只读审查，再决定是否吸收任何具体实现。
