## 1. 永久使命

**Zevorinth 的终极方向是价值创造型智能系统**——能够持续发现价值机会、理解复杂问题、组织知识与资源、发起并执行项目、衡量成果、复盘改进，并在严格治理下持续提升自身能力。

这不是 V1 的能力声明。V1 不自动投资、不自动交易、不自动操作资金。财富创造是长期价值动机，前提是先具备可靠的认知、执行与治理能力。

## 2. 产品身份

**Zevorinth 是本地优先、证据优先、以真实任务交付为核心的通用 AI Agent 工作台。**

用户通过自然语言提出目标，系统负责：理解目标 → 识别任务类型 → 发现缺失信息 → 澄清 → 制定计划 → 识别工具与资源 → 评估权限与风险 → 请求审批 → 调用真实工具 → 管理任务状态 → 验证中间步骤与最终成果 → 处理失败与恢复 → 交付可继续修改的成果。

用户不应需要理解内部 task ID、artifact ID、SHA-256、JSON schema、事件类型、Policy、Lease、Evidence DAG 或数据库结构——这些是可靠性的内部机制，不是用户的前置知识。

来源：与 `PRODUCT_BASELINE.md` 的产品使命定义一致。

## 3. 核心用户价值

| 价值 | 含义 |
| --- | --- |
| 理解 | 正确理解用户自然语言目标 |
| 澄清 | 必要时向用户提出有价值的澄清 |
| 规划 | 生成可检查的有界计划 |
| 执行 | 调用真实工具完成工作 |
| 验证 | 独立验证中间步骤与最终成果 |
| 交付 | 交付可检查、可继续修改的成果 |
| 恢复 | 失败或中断后安全恢复 |

核心原则：**先真正完成任务，再用证据持续变强。**

## 4. 设计哲学

1. **目标优先，而非工具优先**——用户表达目标，系统选择工具；工具是内部能力，不是用户入口。
2. **真实任务优先，而非技术指标优先**——代码行数、测试数、工具数、协议数不等于产品成功；用户能否完成工作才是。
3. **本地优先，不排斥云端智能**——用户数据与工作空间由用户控制，本地执行与验证是核心；模型可本地/云端/混合，但模型选择、数据发送、费用与权限须透明可控。
4. **证据优先，而非模型自信优先**——模型声称成功 ≠ 文件真实存在 ≠ 产物正确 ≠ 测试通过 ≠ 用户旅程通过 ≠ 生产信任。所有重要成功状态必须有相应证据。
5. **人类掌握最终控制权**——用户可查看/修改计划、批准/拒绝操作、暂停/恢复/取消任务、查看成果、撤销允许撤销的操作。模型认为合理不等于自动获得执行权限。
6. **安全是系统基础，不是附加功能**——安全嵌入整个执行链路：授权、边界、隔离、变更记录、独立验证、失败关闭、可恢复。
7. **能力渐进开放**——观察→分析→建议→候选→批准→受控执行→独立验证→授权范围内自动执行。技术可自动化不等于默认应自动化。
8. **长期积累，而非每次从零开始**——逐步形成用户偏好、项目上下文、任务历史、决策记录、可复用技能、领域知识。记忆须可管理、可追溯、可纠正、可删除，不将未经验证的模型猜测固化为事实。

来源：与项目 ADR-001/002/003、`PRODUCT_BASELINE.md` 架构原则、`DESIGN.md` 设计原则一致。

## 5. 目标架构（八层逻辑架构及当前实现度）

逻辑架构，非八个微服务。当前保持本地模块化单体，仅在明确性能/隔离/可靠性/扩展需求时拆分。

| 层 | 职责 | 当前实现度 | 缺口 |
| --- | --- | --- | --- |
| 用户交互层 | 自然入口、任务中心、成果预览、审批、状态 | 部分实现：loopback 只读工作台 + 受控操作面板（vanilla HTML/CSS/JS） | 非对话式主交互；术语面向开发者；SSE 流式已实现（P1-2 完成） |
| Agent Orchestration | 理解、澄清、规划、工具选择、重规划、会话/任务管理 | 部分实现：`service.py`(6719行) + `conversation_service.py`(意图分类+澄清) | LLM 只生成单步候选，多步不被 LLM 选择；无自然语言中途修改；无重规划 |
| Model Gateway | 模型适配、路由、成本、超时、降级 | 部分实现：`llm_planner.py` OpenAI/DeepSeek 双 Provider | 无多模型路由/降级/预算控制策略 |
| Task Execution Engine | 生命周期、依赖、状态转换、暂停、恢复、幂等、调度 | 已实现且验证：`state_machine.py`(14态) + `multi_step.py`(≤8步DAG) + 租约围栏 + 崩溃恢复 | 自动重试/自动恢复未实现；partial success 是终态需新建任务 |
| Tool Runtime | 真实工具调用，输入输出契约 | 部分实现：7 受控工具（write/read/modify_text_artifact、inspect_workspace、edit_text_file、research_report、run_tests） | 无 shell、无浏览器、无网络访问（`not_implemented`） |
| Security & Policy | 权限判定、安全边界、隔离、审计、回滚 | 已实现且验证（最强项）：`policy.py` + `safety_gate.py` + 租约 + control token + CSRF + loopback | — |
| Evidence & Verification | 证明实际发生了什么、成果是否符合目标 | 已实现且验证：`verifier.py` + `event_store.py`(事件溯源) + `assurance.py` + 三态执行真实性 | — |
| Persistence & Knowledge | 长期数据、任务记录、项目上下文、知识积累 | 部分实现：SQLite + 文件存储 | 无跨任务记忆、无知识库、无向量检索（`not_implemented`） |

**模型与内核的根本分工（不可违反）**：模型负责理解与提出方案，内核负责授权与执行，Verifier 负责独立证明结果。模型不得绕过 Policy、自行授权、伪造执行成功、伪造工具结果、修改正式证据、将候选直接当作可信任务、自行宣布测试通过。来源：ADR-003。

### 5.1 任务状态机（当前实现 vs 目标交互状态）

**当前持久化状态机（`state_machine.py` 实测，14 个状态）**：

`queued` / `running` / `awaiting_clarification` / `blocked` / `verifying` / `succeeded` / `partial` / `failed` / `planning_failed` / `interrupted` / `cancelled` / `simulated` / `paused` / `awaiting_approval`

合法转换由 `ALLOWED_TRANSITIONS` 唯一声明。终态：`succeeded / partial / failed / planning_failed / cancelled / simulated`。

**目标交互层状态（尚未实现的用户友好概念，非持久化状态）**：

- `draft`——计划预览未确认（当前由 control center 的 preview + confirmation 实现，无独立状态）
- `awaiting_confirmation`——等待用户确认创建（当前由 queued + confirmation 流程覆盖）

这两者是产品交互层概念，不得混入持久化状态机，除非经独立设计变更并更新 `state_machine.py` 与测试。

> 校正说明：外部战略文档曾列出 `awaiting_approval / paused / partially_succeeded` 作为目标态，但实际 `state_machine.py` 已有 `AWAITING_APPROVAL / PAUSED / PARTIAL`——这三者是已实现的持久化状态，不是未来设计。外部文档遗漏了 `blocked / verifying / planning_failed / simulated`。

## 6. 产品边界

### Zevorinth 是

- 本地优先、证据优先的通用 AI Agent 工作台
- 以真实任务交付为核心
- 模型规划 + 确定性内核执行 + 独立验证

### Zevorinth 不是

- **聊天窗口换皮**——只聊天不完成任务、不操作工具、不交付成果，价值不足
- **节点编排演示平台**——工作流可视化可以是能力，但不能要求用户理解内部 DAG
- **多 Agent 角色扮演平台**——Agent 数量不是智能衡量标准；需要可靠协作，不是大量互相对话
- **开发者审计控制台**——安全/哈希/证据须转化为普通用户可理解的信息
- **单一工具执行器**——文件/代码/shell 只是工具能力，不是产品全部
- **只展示计划而不完成工作的规划器**——成功标准是经验证的成果，不是看起来合理的计划

## 8. 战略治理与方向约束

### 8.1 证据纪律

- 文档描述不等于代码事实；重要状态须结合当前实现与测试确认。
- 历史失败不被新文档覆盖；新验收产生新证据并明确关联之前状态。
- 定向测试 PASS ≠ 端到端 PASS ≠ 真实用户旅程 PASS ≠ 真实模型质量 PASS ≠ 产品验收 PASS ≠ 生产信任。
- 不得将未运行的测试标记为 PASS；不得将推测结果标记为已验证；不得把用户提供的证据说成独立核验的证据。

### 8.2 当前信任边界（不得擅自改变）

- `PRODUCTION_TRUST = false`（来源：`V1_USER_JOURNEY_ACCEPTANCE.md`）
- 本宪章不授予任何 Git 操作、生产发布或历史证据修改权限。

> 关于外部战略文档曾列的 `PERSISTENT_PUBLICATION_ANCESTRY_SUPPORTED / MUTATION_EXECUTION_TRUST_SUPPORTED / TEST_EXECUTION_TRUST_SUPPORTED / merge_ready / status=NOT_VERIFIED`：全项目 grep 查无权威来源，本宪章不采纳为当前事实。仅 `PRODUCTION_TRUST` 有 `V1_USER_JOURNEY_ACCEPTANCE.md` 与 `PRODUCT_RECOVERY_*.md` 的权威出处。

### 8.3 V1J-FILE-01 状态表述（证据对账，2026-11-21 核对）

- **历史 FAIL@205047Z**：真实控制中心验收，续版本须手工填 `source_task_id`/`expected_sha256` + 空 runtime 无友好状态。FAIL 记录完整保留于 `artifacts/audits/v1j-file/20261110T205047Z/`。
- **文档记录 PASS@211309Z**：真实浏览器控制中心、fresh runtime、完整旅程（创建 report.md→独立验证→"继续修改此产物"→自然语言 append→report-v2.md→独立验证→源字节不变→重启持久），证据含 6 张截图 + `revision-lineage.json` + 104/104 回归 + 歧义处理验证。修复点（control center 初始化空 store、"继续修改此产物"入口、服务端绑定 source context）代码已确认存在。
- **准确表述**：V1J-FILE-01 文档记录 PASS，证据经文档+代码层核对支持该结论（非仅报告文字）；历史 FAIL 保留；未经本轮独立浏览器复测，但 PASS 证据充分。

### 8.4 禁止方向漂移

1. 不许工程机制取代产品目标——不把 Zevorinth 重定义为单步证据系统/Evidence DAG 平台/审计系统/安全协议研究项目。
2. 不许把验证系统变成产品本身——证据/哈希/manifest/测试/审计是内部能力，用户真正需要的是完成工作的能力。
3. 不许只追工具数量——增工具前须说明它解决哪类真实用户问题。
4. 不许过早追求多 Agent——任务/权限/状态/记忆/执行/验证成熟前不为展示智能引入大量 Agent。
5. 不许过早建设自动自进化——自改进须建立在成熟测试/隔离/评测/审批/灰度/回滚基础上。
6. 不许以技术便利牺牲用户体验——系统适应用户，不是用户学习内部 schema。
7. 不许用新文档掩盖旧问题——历史失败、未验证状态、风险必须保留。

### 8.5 实施纪律

- 全面实施分解为独立工作格，每格明确目标/价值/依赖/改动范围/安全边界/测试/验收/回滚/证据/剩余风险。
- 高风险工作独立规划，不夹带在普通产品改造中。
- 每格完成后更新 `capabilities.py` 能力注册表与 `product-implementation-roadmap.md`。

## 9. 三层稳定结构（核心约束）

| 层次 | 定义 | 作用 |
| --- | --- | --- |
| 永久方向 | 价值创造型智能系统 | 决定 Zevorinth 最终为什么存在 |
| 产品身份 | 通用 AI Agent 工作台 | 决定用户通过它完成什么工作 |
| 当前基础 | 受控执行内核 | 决定现在从哪里出发、每步能可靠做到什么 |

**关键警示**：不能因为目前拥有的是执行内核，就把整个产品定义成执行内核；也不能因为终局是价值创造型智能系统，就跳过可靠的产品与工程阶段。这两种方向漂移过去都曾影响项目。今后每次架构设计、功能开发、技术升级都应回答：**它是否让 Zevorinth 更接近成为一个能真正帮助用户完成工作、持续积累能力并创造价值的智能系统？** 不能清楚回答，就不应仅因技术有趣而投入实施。
