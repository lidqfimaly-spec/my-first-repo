# 第 1.5 阶段可靠性与并发审计

日期：2026-10-19
基线提交：`752cae3 feat: establish verified artifact task loop`

## 1. Phase 1 实际执行时间线

| 时点 | 状态变化 | 持久化内容 | 文件副作用 |
| --- | --- | --- | --- |
| T0 | 无 -> `queued` | 创建 Task 快照和 `task_created` 事件，同一事务提交 | 无 |
| T1 | `queued` -> `running` | 计划快照和 `task_planned` 事件，同一事务提交 | 无 |
| T2 | `running` 保持 | `tool_started` 事件、执行模式和阶段更新，同一事务提交 | 无 |
| T3 | 工具内部 | 临时文件写入、`fsync`、原子链接目标文件 | 真实文件已经出现 |
| T4 | `running` 保持 | 工具结果与产物证据、`tool_succeeded` 事件提交 | 文件已存在 |
| T5 | `running` -> `verifying` | 检查点和 `verification_started` 事件提交 | 文件已存在 |
| T6 | 独立读取 | Verifier 重新读取文件、比较内容和证据 | 无写入 |
| T7 | `verifying` -> 终态 | 验证结果、终态事件提交 | 无写入 |

计划或策略阻断分别发生在 T1、T2 之前，均在同一状态事务中记录事件。

## 2. 已确认的可靠行为

- 单个状态转换会重新读取数据库当前状态，校验转换，然后同时更新快照和插入事件。
- 终态不能被普通状态转换回退。
- `succeeded` 必须经过独立 Verifier。
- 工具写入使用临时文件和“不覆盖”的原子硬链接。
- 文件缺失、修改或工具证据不一致都不会被宣告成功。
- 测试数据库与产物位于临时目录。

## 3. 已确认的并发与恢复缺口

### R1：缺少持久化执行权和租约

Phase 1 没有 owner、lease token、lease expiry 或 claim generation。并发保护主要依赖“状态转换恰好竞争”，而不是显式执行权协议。不同执行路径没有统一的认领入口。

### R2：新实例会误伤正在执行的另一实例

`TaskService.__init__` 当前会把所有 `running`、`verifying` 任务立即改为 `interrupted`。若另一个进程仍持有活动执行，启动查询或第二执行者会错误改变其状态。

### R3：没有围栏令牌

若执行者的租约过期而新执行者取得任务，旧执行者仍可能继续写文件或提交旧结果。仅比较任务状态不足以阻止过期写入者覆盖新终态。

### R4：统一认领协议缺失

`submit` 的新任务通常能靠 `queued -> running` 原子转换互斥，但这只覆盖一条路径。没有公开的“运行既有任务”协议，也没有统一的 `resume`/正常执行竞争入口。

### R5：SQLite 锁失败缺少统一错误语义

数据库内设置了有界 `busy_timeout`，但锁超时最终可能以原始 `sqlite3.OperationalError` 暴露。CLI 没有明确的存储忙/失败退出码。

### R6：文件已写但工具证据未提交的恢复窗口

若进程在文件原子提交后、`tool_succeeded` 事务前死亡，数据库仍只有 `tool_started`，没有工具证据。当前恢复不会把该文件假定为成功产物；后续重写会因“文件已存在”失败。这比覆盖安全，但缺少明确的“未追踪产物”诊断。

### R7：数据库更新失败后的状态

若文件已经写入但后续 SQLite 更新失败，任务会保留执行中的检查点或携带仍有效的租约。必须依赖租约过期和显式诊断，不能从工具返回或文件存在推定成功。

### R8：进程内状态不能代替跨进程互斥

TaskService、Writer、Verifier 均无进程内锁，且即使增加 `threading.Lock` 也不能满足同一 SQLite 数据库的多进程范围。互斥必须由数据库事务完成。

## 4. 最小必要调整

1. 在 Task 快照中增加 `execution_owner`、`lease_token`、`lease_expires_at`、`claim_generation`。
2. 在 SQLite `BEGIN IMMEDIATE` 事务中统一认领任务；活动租约存在时拒绝第二执行者。
3. 所有关键执行更新携带 lease token；token 不匹配时拒绝旧执行者提交。
4. 新实例只把“已过期租约”的进行中任务转为 `interrupted`；活动租约保持不动。
5. 终态转换清除租约；认领、拒绝、过期和释放全部写入事件。
6. 增加有界 SQLite 等待和明确的 `StoreBusyError`/CLI 退出码。
7. 增加真实 SIGKILL、并发同任务、恢复竞争、不同任务并发和异常恢复测试。

## 5. 明确不声称

- 不实现跨机器或分布式执行。
- 不声称文件系统具备分布式围栏能力。
- 不声称现有测试覆盖断电、磁盘故障或文件系统损坏。
- 不用内存锁冒充跨进程互斥。
