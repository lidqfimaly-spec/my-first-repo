# P0 · 产品形态比较与推荐

`[P0_PRODUCT_FORM_RECOMMENDATION · 2026-11-22]`

> 结论先行：**V1 保持"本地服务 + 浏览器 UI"，但按"可被桌面壳包装"的约束来设计；
> 不要现在做桌面壳，也不要转云。**
> 理由不是"本地优先所以桌面优先"，而是：**异步执行一旦落地，浏览器形态的主要缺陷就消失了，
> 而桌面壳的主要成本（打包、签名、更新）不会消失。**

## 1. 已被事实约束的前置条件

| 事实 | 对形态的硬约束 | 证据 |
| --- | --- | --- |
| 核心工具是本地文件/进程（写文件、改代码、跑测试、只读 shell） | 执行体必须在本机 | `policy.py`、`local_test_runner.py`、`shell_tool.py` |
| 服务只绑 loopback，且 CLI 不暴露 host | 现状就是"本机单用户" | `workbench_server.py:47,1604-1614` |
| 零第三方运行时依赖 | 打包成本主要来自 Python 运行时，不是前端 | `pyproject.toml:11` |
| 执行同步阻塞在 HTTP 线程 | 关掉页面 = 请求被中断（写操作在 policy 阶段就拦，但长任务会断） | `service.py:431-443` |
| 有租约 + 执行预算（60 s / 600 s） | 后台常驻进程需要处理崩溃恢复 | `service.py:323-324` |
| 数据在本地 SQLite + 本地目录 | 换设备 = 数据不跟随 | `data/zevorinth.sqlite3`、`artifacts/` |
| 单用户（无多租户、无账号） | 不需要登录体系、不需要多端同步 | `session:"authentication":"none"` |

| 维度 | A. 本地服务 + 浏览器（现状） | B. 桌面壳（Tauri/Electron 包一层） | C. 双端（Web 云 + 本地 agent） | D. CLI 优先 |

## 3. 推荐：A 为 V1，B 为 V1.1（条件触发）

### 3.1 为什么不是 B（现在）

桌面壳解决的是：系统集成、后台常驻、安装体验。
但**这三件事的主因是"执行绑定在浏览器请求上"**。一旦 F-04（异步执行 + 队列）落地：

- 关页面不再中断任务 → 后台常驻的需求从"必须"降为"方便"；
- 托盘/通知可以先用浏览器通知 API（`Notification`）顶一阵；
- 剩下真正需要壳的只有：文件选择对话框、开机自启、单实例、自动更新。

这四项合计是 S 级工作量，**且都可以在"已有 HTTP + 静态资源"之上加壳实现，不需要重写 UI**。
所以正确顺序是：先把异步做掉，再看还剩多少理由需要壳。

### 3.2 为什么不是 C（云 + 本地 agent）

- 单用户、本地数据、本地执行 → 云唯一的增量价值是"跨设备"，而跨设备不是当前痛点（用户在同一台 Mac 上工作）。
- 引入云就引入：账号体系、数据出境策略、云↔本地桥的鉴权（这是最高危的攻击面）、运维成本。
- 与"本地优先、证据优先"的定位直接冲突。

`INFERENCE`：Cursor 的 Cloud Agents 之所以成立，是因为它的产物是 PR（天然在云端），交付面不需要本地文件。Zevorinth 的产物是本地文件，云端没有落点。

### 3.3 为什么不是 D（CLI 优先）

CLI 已经存在且完整（`run`/`test`/`resume`/`recover`/`conversation`/`approve`…），
但它要求用户知道 `operation` 枚举与参数名——这正是 J1 失败的同一个原因。
把 CLI 当主界面，等于把"用户必须懂内部模型"制度化。

**CLI 保留为"高级/自动化入口"，不作主界面。**

## 4. A 形态要补的三件事（都属于 V1）

| 缺口 | 现状 | V1 处置 |
| --- | --- | --- |
| 后台常驻 | CLI 进程一关就没了 | 提供 `--daemon` 或 launchd plist 生成命令；文档写清"关终端不影响执行" |
| 单实例与端口 | 端口冲突未处理 | 启动时检测并复用已运行实例（读 `data/*.port`） |
| 系统通知 | 无 | 浏览器 `Notification` + 页面内 attention 计数（已有数据） |

## 5. 迁移成本（若 V1.1 决定加壳）

| 项 | 成本 | 说明 |
| --- | --- | --- |
| 复用现有 UI | 0 | 壳内直接 `WebView` 加载 `http://127.0.0.1:<port>` |
| Python 运行时打包 | M | PyInstaller / Nuitka；零依赖使体积可控（无 numpy 等） |
| 代码签名 + 公证（macOS） | M（一次性） | 否则用户首次打开需绕过 Gatekeeper |
| 自动更新 | M | Tauri updater 或 Sparkle |
| 三平台适配 | L | Windows 的路径/权限/杀软误报是主要风险 |
| 双形态并存（壳 + 浏览器） | S | HTTP 接口不变，天然并存 |

**结论：迁移成本主要在"分发"，不在"产品"。所以可以放心推迟。**

## 6. 尚待验证的关键假设

| # | 假设 | 若不成立的后果 | 怎么验 |
| --- | --- | --- | --- |
| H1 | 用户只需在一台机器上工作 | 跨设备需求成立 → 需重新评估 C | 观察真实使用是否出现"换机继续"诉求 |
| H2 | 单用户共享本机权限是可接受的安全边界 | 若需隔离他人使用 → 需账号与多租户 | 是否出现多人共用一台机 |
| H3 | 浏览器通知足以替代系统通知 | 否则壳的优先级提前 | 长任务场景下用户是否漏看 |
| H4 | 本地文件是主要交付物 | 若交付物变成网页/PR → 形态需重评 | 统计真实任务产物类型 |
| H5 | 用户能接受"起服务再开页面" | 否则需要壳来降低门槛 | 首次使用流失点 |
