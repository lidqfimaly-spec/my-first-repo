# P0 · 执行摘要

`[P0_AUDIT_COMPLETE_PENDING_REVIEW · 2026-11-22]`

> 一句话：**Zevorinth 有一个 L4 级的验证内核，和一个 L1 级的产品入口。**
> 用户今天拿到的是"能安全执行结构化指令的引擎"，不是"能听懂目标并交付成果的 Agent"。

---

## 1. 当前真实状态（三条硬事实）

### 事实一：产品执行路径上没有模型

`TaskService` 默认 `DeterministicPlanner`（`service.py:361`），控制中心显式传入（`workbench_control.py:586,1157`），
产品面（server / control / conversation）**零 LLM 引用**。`llm_planner.py` 只在 CLI 环境变量下启用，且只能选 2 个操作。

**含义**："智能"目前来自表单字段与固定规则。用户说"把这段内容存成 note.txt"，系统回答"请提供 operation"。

### 事实二：引擎能力远超产品能力

| 能力 | 引擎 | 产品 |
| --- | --- | --- |
| 多步计划（≤8 步、依赖、审批、部分成功） | ✅ 已实现并有测试 | ❌ 可创建、**不可启动** |
| `run_tests` | ✅ 容器/host 双后端 | ❌ 可创建、**不可启动** |
| 精确编辑（摘要前置 + 备份 + 原子写 + 重验） | ✅ | ✅（需用户自己算 sha256） |
| 独立回读验证 | ✅ 7/8 工具 | ✅（结论不翻译成人话） |
| 跨任务记忆 | ✅ 存储完整 | ❌ **不被任何决策读取** |

### 事实三：十类旅程 1 PASS / 4 PARTIAL / 5 FAIL

（详见 `P0_USER_JOURNEY_AUDIT.md`；唯一 PASS 还在引擎层）

| 场景 | 结果 | 关键卡点 |
| --- | --- | --- |
| 首次进入 + 简单目标 | FAIL | 要内部字段名；`你好` 变成待办任务 |
| 多步骤复杂目标 | FAIL | 多步不可启动 |
| 执行中追加要求 | FAIL | 无"追加"语义；同步执行无法插话 |
| 修改计划 | PARTIAL | 有 replan，但审批可被绕过 |
| 暂停/恢复/取消 | FAIL | 单步不可暂停；运行中不可取消 |
| 工具失败 | PASS（引擎） | 失败安全、错误码准；文案是开发者语言 |
| 部分成功 | PARTIAL | 判定正确，产品无入口，且不可续做 |
| 检查/修改/重交付 | FAIL | 无下载、无版本；改一个字要自己算摘要 |
| 知道在做什么 | FAIL | 问"进行到哪了"被判成"澄清答案" |
| 知道要授权什么 | PARTIAL | 审批不给参数；host 授权只在 CLI |

## 2. 核心产品能力（可保留并放大的资产）

1. **`SUCCEEDED` 只能从 `VERIFYING` 进入**（`state_machine.py:24-108`）——机制上禁止"工具说成功就算成功"。
2. **独立回读验证**：写完重读比字节、改完重解析核对血缘、报告重建重算摘要（`verifier.py:109-137` 等）。
3. **事后漂移可检测**：`artifact_observation.matches_registration`。
4. **失败安全**：两个实测用例（`text_match_count`、`source_file_changed`）都在 policy 阶段被拦，文件零改动。
5. **零第三方依赖、全靠本机、loopback 绑定**——可审计、可移植。

`INFERENCE`：这五条是竞品普遍不强调的（已核实的 4 家都在"能干活"上竞争，很少讲"失败可证"）。
**这是唯一值得写成对外一句话的差异化。**

## 4. 竞品结论（只讲有官方来源的）

| 产品 | 值得抄的机制 | 对 Zevorinth 的成本 |
| --- | --- | --- |
| Cursor | **追加要求排队到下一个 tool call**，不打断执行 | 低（已有 6 个检查点） |
| Dify | 人工介入是"节点"：表单 + 多决策分支 + **超时/转交** | 中（当前审批零信息） |
| Claude | Artifact 版本 + diff + **五页签溯源**（执行日志优先于代码） | 中（数据结构已够） |
| Claude | 授权按范围：Once / 会话 / 项目 / 全局 | 低（grant 机制已有） |

**共同点（仅基于已核实来源）**：没有一家把内部字段名暴露给用户；没有一家用同步阻塞 HTTP 跑长任务；审批都给足信息。

其余 7 个产品（ChatGPT/Gemini/Codex/Windsurf/Perplexity/NotebookLM/n8n）本轮无官方来源，
仅作方向登记，**不得写进对外材料**。

## 5. 产品形态建议

**V1 保持"本地服务 + 浏览器"，按"可被桌面壳包装"约束设计；不做桌面壳、不做云。**

理由：异步执行一旦落地，浏览器形态的主要缺陷（关页面即断）消失；桌面壳的成本（打包/签名/更新）不会消失。
形态不是现在的瓶颈。
