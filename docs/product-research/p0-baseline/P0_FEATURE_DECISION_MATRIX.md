## 2. 伪功能检查（界面有、能力没有）

> 规则：**界面上的每个动作，背后必须有一个真机制；没有就做成禁用 + 说明，不许做成能点。**

| 功能 | 表面交互 | 底层真实依赖 | 现状 | 处置 |
| --- | --- | --- | --- | --- |
| 暂停任务 | 暂停按钮 | 工具级中断 / 步边界检查点 | 单步无检查点；仅多步可用（`service.py:3278`） | 只对多步任务显示；单步显示"不可暂停（单步任务）" |
| 取消任务 | 取消按钮 | 安全点 + 租约语义 | 引擎拒绝活跃租约；无路由 | 先做"请求取消"，状态显示"已请求，将在下一步停止" |
| 修改计划 | 计划编辑器 | 依赖重算 + 审批失效 | `replan` 存在但不清 `approved_step_ids` | **先修审批失效，再放编辑器** |
| 进度条 | 百分比 | 真实进度事件 | 只有事件序列，无总量 | 不做百分比；做"步骤流 + 当前步骤" |
| 审批 | 批准按钮 | 审批绑定内容摘要 | 只绑 step_id | 先加内容摘要，再美化表单 |
| 版本管理 | 版本列表 | 版本模型 + 原子交付 | 无版本概念 | **DEFERRED**（先做下载 + 血缘卡片） |
| 任务取消后清理 | "已取消" | 副作用处理 | 写操作在 policy 阶段就拦，无副作用 | 安全，可直接显示 |

## 3. 核心闭环审查（四类 V1 代表性任务）

| 任务类型 | 当前闭环程度 | 断点 | V1 必须补 |
| --- | --- | --- | --- |
| **A 文件任务**（自然语言 → 写/改文件 → 交付） | **半闭环**：能完成，但要 4 轮内部字段；能预览不能下载 | J1、J8 | F-01、F-02、F-03、F-12 |
| **B 代码任务**（工作区检查 → 改代码 → 验证 → 报告） | **半闭环**：`edit_text_file` 很扎实（摘要前置 + 备份 + 原子写 + 重验），但目标必须手填参数 | J1、J6 | F-01、F-25；变更报告可先用 `inspect_workspace` 拼 |
| **C 研究任务**（搜集 → 引用 → 报告） | **伪闭环**：`research_report` 只从**本地 workspace 源文件**生成，要求精确引文；**不联网检索** | 无检索能力 | F-01；检索能力 `NEEDS_VALIDATION`（是否引入网络是产品决策） |
| **D 复杂规划任务**（多步 → 审批 → 恢复 → 交付） | **引擎闭环、产品断裂** | J2、J5、J7 | F-04、F-09、F-11、F-08 |

`FACT`：C 类最关键的一条是——**`research_report` 不是"研究"，是"按给定引文拼装 Markdown"**（`research_workflow.py:229` 起）。把它宣传成"研究"会直接制造"错误成功率"。

## 4. MUST_HAVE_V1 的验收标准（可测）

| ID | 验收标准（必须能被第三方按此判定） |
| --- | --- |
| F-01 | 输入 10 条自然语言目标（含"把内容存成 x.txt"、"改 calc.py 的 bug"、"总结 docs/a.md"），**≥8 条无需用户提供任何内部字段名即可生成可执行计划**；非法抽取必须被代码拒绝并给出可读原因 |
| F-02 | 每条澄清问题含：字段的用户语言名称 + 1 个示例 + 合法候选（枚举字段）；答案经校验后才写入；非法答案当场提示，不产生 `"operation": "写文件"` 这类脏值 |
| F-03 | 任意一轮对话后，`GET .../messages` 至少包含 1 条 `assistant` 消息，且澄清问题可在会话中回看 |
| F-04 | `POST /control/api/tasks` 返回 ≤ 500 ms；执行在后台；同一时刻 ≥2 个任务可并行；关闭浏览器不影响执行 |
| F-09 | 多步任务可从 UI 创建并启动；`GET .../actions` 对 `execute_plan` 提供 `start_queued_task` |
| F-11 | 审批页展示：将执行的工具、完整参数、将产生的副作用、目标文件当前摘要；无审批时不得执行（负向测试：跳过审批直接 resume 必须失败） |
| F-12 | `GET /api/tasks/{id}/artifact?download=1` 返回 `Content-Disposition: attachment` 与正确字节；>64 KiB 也能下载（预览仍可限制） |
| F-16 | 任务详情显示"第 n/m 步 + 正在做什么（工具的用户语言名）+ 已完成项"，且与事件序列一致 |
| F-25 | 失败任务页面提供"按当前文件状态重试"，一键完成摘要刷新 + 重新提交；不要求用户离开页面 |

## 5. V1 范围建议（一句话）

**做"能听懂人话 + 能异步跑 + 能拿回成果 + 失败能继续"这四件事，其余全部推后。**

具体：F-01/02/03/04/09/11/12/16/25 九项；F-05/06/08/13/15/17/18 作为紧随其后的第二波。
明确不做：F-30 多 Agent、F-31 积分、F-32 伪暂停按钮。
