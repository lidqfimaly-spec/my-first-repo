## 2. 关键瓶颈（按"解锁下游数量"排序）

| 排名 | 瓶颈 | 解锁下游 | 为什么 |
| --- | --- | --- | --- |
| 1 | **A1 理解层** | 澄清质量、多步生成、首次体验、M-07 | 没有它，所有输入都是"用户手填参数" |
| 2 | **A5 异步执行** | 暂停/取消、追加要求、续跑、并行、长任务交付 | 同步模型让"干预"无处安放 |
| 3 | **A4 审批绑定** | 审批表单（否则只是装饰）、安全信任 | 只绑 step_id，replan 可绕过 |
| 4 | **A8 交付** | 用户价值实现（M-01/M-08 解锁的前提） | 拿不走 = 没完成 |
| 5 | A7 续跑 | 长任务可用性 | 依赖异步才有意义 |
| 6 | A9 记忆 | 个性化与效率 | 依赖 A1/A3 有决策回路 |

**A6（验证）不是瓶颈，它是资产。** 它已经 L4，且是全系统唯一能对外讲"我们不假装成功"的东西。

## 4. 三个"看起来能解、实际解不动"的陷阱

| 陷阱 | 为什么解不动 |
| --- | --- |
| 只加"暂停按钮" | 单步工具不可中断（`subprocess.run` / 单次文件写），按钮只能变成装饰 |
| 只加"多步计划 UI" | `execute_plan` 不可启动；放开了也需要"计划从哪来"（A1/A3） |
| 只加"记忆面板" | 记忆不被任何决策读取，面板只会让人以为系统记住了 |

## 5. 建议的解锁顺序（与具体工作项对齐）

```
第 1 步  A5 异步执行（R-03 / F-04）           ← 先把"能跑很久"这件事做对
第 2 步  A1 理解层 + A2 澄清（R-01 / R-18）   ← 让用户说人话
第 3 步  A8 交付（R-10 / F-12）               ← 让成果能拿走
第 4 步  A3 多步入口（R-02 / F-09）           ← 让复杂任务成立
第 5 步  A4 审批绑定 + 表单（R-08 / F-11）     ← 让安全可信
第 6 步  A7 续跑（R-19 / F-08）               ← 让长任务不白跑
第 7 步  A9 记忆注入（R-07 / F-18）            ← 最后再谈"变强"
```

理由：前四步任意一步缺失，后面都只是"更精致地做不到"。
