`[P0_NEXT_PHASE_ROADMAP · 2026-11-22 · 仅提案，未获实施授权]`

## S-A · 执行基座：异步 + 可请求取消 + 可读进度

**解决的问题**：J3/J5/J9；R-03 / R-04 / R-15 / F-04 / F-16

| 项 | 内容 |
| --- | --- |
| 建设目标 | 提交即返回；执行在后台；进度人类可读；可请求取消并在安全点停止 |
| 用户问题 | 长任务期间页面卡死；关页面就断；不知道在干什么；停不下来 |
| 依赖能力 | 现有检查点（6 处）、租约续租、SSE |
| 实施范围 | ① 单进程执行器 + SQLite 队列 ② `POST .../cancel`（请求取消，非强杀） ③ 事件 → 人话映射（"正在写 note.txt"） ④ SSE 断连提示与重连 |
| **不包含** | 单步工具级中断（不做 force kill）；多进程/分布式 |
| 交付物 | 执行器模块、取消路由、进度文案表、SSE 心跳与断连状态 |
| 验收标准 | 创建接口 P95 < 500 ms；2 任务并行；关闭浏览器后任务完成；取消请求 ≤1 步内生效且状态文案一致；断网 10 s 内提示 |
| 风险 | 全局锁与续租线程的交互；`data/*.sqlite3` 并发写（WAL 已开） |
| 预估 | 1.5–2 周 |
| 前置 | 无（可立即开工） |

**停止条件**：一旦"提交即返回 + 进度可读"成立，本阶段结束。**不许顺手做任务调度策略/优先级/配额。**

## S-B · 听懂人话：受约束理解 + 有意义的澄清 + 会说话的会话

**解决的问题**：J1；R-01 / R-18 / R-05 / R-06；F-01 / F-02 / F-03

| 项 | 内容 |
| --- | --- |
| 建设目标 | 自然语言 → 结构化请求；澄清用用户语言且答案被校验；会话里能看到系统说的话 |

| 依赖能力 | `planning_validation.py`（现成的输出校验）、8 个操作的参数 schema |
| 实施范围 | ① 理解层：模型输出候选（operation/实体/置信度），代码校验 + 枚举白名单 + 兜底澄清 ② 澄清模板：字段用户语言名 + 示例 + 候选 ③ assistant 消息写入会话 ④ 规划输入加入最近 N 轮 |

| 预估 | 2 周 |
| 前置 | 需要决定"本地模型 vs 远端 API"（隐私/成本）——**产品决策，不由实现方决定** |

**停止条件**：8 条以上自然语言目标可通过。**不许顺手做"意图无限扩展"**（聊天、闲聊、多轮闲聊都不要）。

## 2. 防止再次陷入"验证基础设施循环"

`FACT`：仓库里有 20 个审计/评测资产（7 个审计与变异执行器 + 12 个审计类测试 + 1 个证据脚本）、
905 项历史通过用例（当时的树）、变异测试、外部锚点链；
而产品侧 10 条旅程有 5 条 FAIL。这正是"工程验证进度替代产品能力进度"的形态。

因此对后续任何"完整性/安全"类工作，附加四条约束（建议写入项目规则）：

1. **必须点名它阻塞了哪一条真实旅程**（如"R-08 阻塞 J10"），否则不立项。
2. **不得早于对应旅程的功能项**：先让功能存在，再谈它的完整性。
3. **每个阶段最多一个完整性项**，且不得跨阶段连做。
4. **真实旅程验收优先于完整性验收**：冲突时先让用户能完成任务。

## 3. 建议的开工顺序与理由

```
S-A（执行基座）──→ S-B（理解）──→ S-D（复杂任务）──→ S-E（记忆）
        └────────→ S-C（交付，可并行）
```

- 先 S-A：它是唯一"不依赖任何产品决策、纯工程、且解锁最多下游"的阶段。
- 再 S-B：它需要一次产品决策（模型来源），但决定 J1 生死。
- S-C 可并行：纯增量，风险最低，且立刻让"完成任务"变得有意义。
- S-D 必须在 A+B 之后：否则多步任务只会更快地暴露"计划是手写的"。
- S-E 最后：没有决策回路之前做记忆，是自欺。
