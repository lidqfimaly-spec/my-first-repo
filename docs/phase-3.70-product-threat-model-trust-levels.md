# Zevorinth Phase 3.70：产品威胁模型与证据可信级别

## 1. 结论

**PASS。** 本阶段完成安全设计决策，不引入签名、密钥、网络服务或新恢复 action。

产品决定：

- 当前实现提供 A0 防护和有限的 A1 检测；
- A2 同 UID 全量重写明确不在当前保护范围；
- A3 运行时、内核、root 和文件系统控制明确不在当前保护范围；
- 当前证据最高只能达到 L1；
- L2 / L3 只作为未来设计目标，未实现且审计结果不会返回这些级别；
- 现有低风险 marker 操作可以显示内部一致性，但不能显示身份认证或安全认证；
- 不新增自动恢复、自动重试、自动清理或第二种恢复 action。

## 2. 攻击者等级

| 等级 | 能力 | 当前行为 |
| --- | --- | --- |
| A0 | 意外损坏、崩溃、写入中断 | 防御：schema、digest、intent、崩溃对账 |
| A1 | 可写 workspace，但不能控制审批存储和执行器代码 | 检测文件内容、权限、inode 和已知证据矛盾 |
| A2 | 与 Zevorinth 同 UID，可重写 workspace、审批记录和所有本地摘要 | **未防御**；可能形成内部自洽记录 |
| A3 | root、内核、文件系统、Python 运行时或代码控制者 | **未防御**；可绕过所有进程内检查 |

A1 的边界是“局部修改或仅能写 workspace”的场景。若 A1 同时取得审批目录写权限，则
应视为 A2。

## 3. 证据可信级别

| 级别 | 含义 | 当前实现 | 允许的产品行为 |
| --- | --- | --- | --- |
| L0 | 证据缺失、损坏、矛盾、不可读或当前状态不可验证 | 是 | 只读检查、人工复核；不得显示成功 |
| L1 | 本地记录与当前观察内部一致 | 是 | 可显示 `consistent, not authenticated`；不得自动重试、清理或扩大权限 |
| L2 | 证据来源身份经独立认证 | **否** | 仅设计目标 |
| L3 | 审计或运行环境可独立于本机权限得到证明 | **否** | 仅设计目标 |

`consistent` 不重命名、不升级。审计输出增加：

```text
assurance_level=L0|L1
assurance.label=missing_or_inconsistent|internal_consistency_only
assurance.evidence_authenticated=false
assurance.security_certification=false
```

`assurance_level("L2")` 和 `assurance_level("L3")` 只能返回 `implemented=false`、
`evidence_authenticated=false` 和 `security_certification=false`。

## 4. 状态行为契约

| 审计状态 | 证据级别 | 用户可见行为 |
| --- | --- | --- |
| `consistent` | L1 | 显示内部一致，同时显示来源未认证 |
| `not_claimed` | L1 | 显示未认领；不得显示执行完成 |
| `denied` | L1 | 显示拒绝；文件存在也不能显示成功 |
| `verified_failure` | L1 | 显示失败并进入人工复核 |
| `unverified` | L0 | 显示未验证、人工复核，禁止自动重试 |
| 缺失或损坏记录 | L0 | 显示不可验证，禁止自动恢复或清理 |

API、日志和未来 UI 必须同时暴露 assurance level 与未认证边界。不得仅显示绿色
“成功”而隐藏 `authenticity=not_authenticated`。

## 5. 能力门槛

| 未来能力 | 最低证据级别 | 当前是否允许 |
| --- | --- | --- |
| 现有低风险 marker 的只读一致性审计 | L1 | 是 |
| 自动重试未知副作用 | 至少 L2，且需幂等性证明 | 否 |
| 自动清理 | 至少 L2，且需独立删除授权 | 否 |
| 第二种恢复 action | 先完成操作级威胁模型；涉及 A2 时至少 L2 | 否 |
| 多用户或远程审计认证 | L2 或 L3 | 否 |
| 恶意本机管理员防护 | L3 | 否 |

当前代码不会返回 L2/L3，因此上述能力均保持禁用。

## 6. 可信根方案比较

| 方案 | 保护目标 | 关键假设 | 密钥/可用性风险 | 当前决策 |
| --- | --- | --- | --- | --- |
| 本地额外 SHA-256 | 意外损坏 | 摘要与记录不同时被改 | 不能抵御 A2 | 不采用为可信根 |
| 同 UID Ed25519 签名 | 签名完整性 | 私钥不能被同 UID 进程读取 | 私钥复制、轮换、恢复 | 不足以单独抵御 A2 |
| OS Keychain / Secure Enclave | 硬件隔离密钥 | OS 与安全区可信 | 平台绑定、解锁、备份 | 待产品需求明确 |
| 本地 append-only 日志 | 追加历史 | 日志不可被删除或重建 | A2 可重建 | 不足以单独抵御 A2 |
| 远程 append-only / transparency log | 删除和重写检测 | 远程服务、身份和时间可信 | 网络、隐私、可用性、运维 | 待身份和服务设计 |
| TPM / measured boot / attestation | 运行时和环境来源 | 硬件与供应链可信 | 平台限制、证明验证复杂度 | 仅高价值高权限场景 |

本阶段不选择实现任何方案。若未来 A2 被纳入产品威胁模型，推荐优先评估“硬件隔离
签名 + 外部追加式审计”的组合，而不是继续增加本地摘要。

## 7. 一致性与安全承诺

文档、代码、日志和 API 必须遵守：

- 可以声明“当前记录内部一致”；
- 不可以声明“证据来源可信”；
- 不可以声明“系统安全认证通过”；
- 不可以把 L1 用作扩大自动执行权限的依据；
- 不可以把同 UID 全量重写描述成已防御；
- 任何未知或矛盾状态必须 fail-closed。

## 8. 测试与验证

本阶段验证：

- 审计成功状态返回 L1；
- 损坏状态返回 L0；
- approved / denied 等安全决策返回 L1；
- L2 / L3 的 `implemented=false`；
- L0 / L1 均禁止自动重试和自动清理；
- L2 / L3 不会被错误标记为已认证或安全认证。

最终全量测试数量和 mutation 结果记录在阶段审计摘要中。

## 9. 阶段判定

**PASS**：A0–A3 攻击者边界、L0–L3 证据等级、允许行为、可信根残余风险和用户可见
承诺已经形成一致契约；当前实现明确停留在 L1，不夸大本地摘要的能力。
