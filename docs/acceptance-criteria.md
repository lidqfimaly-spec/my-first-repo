# 首个闭环验收标准

## 全局判定规则

- 测试宣称成功必须有真实工具结果和 Verifier 证据。
- 模拟工具结果必须标记 `SIMULATED`，不能生成“已验证成功”的终态。
- 没有执行必须标记 `NOT_RUN`，不能用空结果冒充成功或失败。
- 每个失败测试必须检查状态、错误类别、事件和副作用，不能只检查退出码。
- 所有文件操作测试都在 `tempfile.TemporaryDirectory()` 内完成。

## A1：简单任务成功

输入：

- 目标明确；
- 产物路径合法；
- 内容非空且未超限；
- 目标文件不存在。

预期：

1. 任务进入 `SUCCEEDED`。
2. `events.jsonl` 记录任务创建、计划、工具请求、真实工具结果、验证和完成。
3. 产物存在且内容一致。
4. Verifier 独立读取文件并报告大小和 SHA-256。
5. 报告显示 `execution_mode=REAL`。

反例：

- 只创建状态文件而未创建产物；
- 工具返回成功但内容不一致；
- 验证器未执行却标记通过。

## A2：工具失败如实报告

注入：

- 工具在写入前抛出受控异常，或产物根目录被替换为不可写目标。

预期：

1. 任务进入 `FAILED`，不得进入 `SUCCEEDED`。
2. 保存工具错误类别和脱敏消息。
3. 不伪造产物，不伪造验证证据。
4. 退出码与失败报告一致。
5. 如果磁盘上留下临时文件，恢复/清理逻辑必须能识别。

## A3：信息不足要求澄清

输入缺少以下任一必填字段：

- `goal`
- `artifact_path`
- `content`

预期：

1. 任务进入 `AWAITING_CLARIFICATION`。
2. 报告准确列出缺失字段和澄清问题。
3. 工具调用次数为 0。
4. 不创建产物。
5. 不把默认猜测写入任务。

## A4：中断识别与安全恢复

测试模拟：

1. 任务进入 `RUNNING` 并写入可识别运行事件；
2. 进程在完成事件前结束；
3. 新进程加载任务。

预期：

1. 新进程能识别 `INTERRUPTED`，并记录检测依据。
2. 不得标记 `SUCCEEDED` 或 `FAILED`。
3. 若产物尚未写入，显式恢复可执行一次工具。
4. 若产物已写入，恢复先验证，不重复覆盖。
5. 恢复生成新 `attempt_id`，旧事件不被重写。
6. 证据不足时保持 `INTERRUPTED` 并报告未知。

## A5：未经授权的危险操作被阻止

至少覆盖：

- `../` 路径逃逸；
- 绝对路径；
- 父目录符号链接逃逸；
- 覆盖已有文件；
- 超出内容上限；
- 未来若加入命令工具：非白名单命令和 shell 注入。

预期：

1. 任务进入 `BLOCKED`。
2. 事件包含拒绝原因和违规参数的安全摘要。
3. 工具调用次数为 0。
4. 允许根目录外没有创建、修改或删除任何文件。
5. 拒绝不能被记录为普通成功或普通失败。

## A6：真实、模拟、未执行可区分

测试矩阵：

| 场景 | ExecutionMode | 是否可产生 SUCCEEDED |
| --- | --- | --- |
| 真实工具 + 真实验证 | `REAL` | 是 |
| 测试替身工具 | `SIMULATED` | 否 |
| 未调用工具 | `NOT_RUN` | 否 |

预期：

1. 三种模式在结构化结果中可机器判定。
2. 事件和报告保留模式，不只存在于测试内部变量。
3. 模拟执行不能生成真实验证证据。
4. 未执行不能写成“通过”“失败”或“等待验证”之外的模糊状态。

## 第 1 阶段完成门槛

- A1、A2、A3、A5、A6 至少有自动化测试。
- A4 至少有确定性中断注入测试；真实进程强杀测试可作为后续加固。
- `python -m unittest discover -s tests -v` 全部通过。
- 另执行一次独立 CLI 冒烟，不以单元测试替代端到端命令。
- 所有测试输出明确记录实际执行的命令和结果。
